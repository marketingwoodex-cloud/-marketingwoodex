## 2. Old design system: deleted, replaced by one layer

| Before | After |
| --- | --- |
| `admin.css` + `woodex-tw.css` + `woodex-ui.css` + `woodex-ds.css` + `woodex-v21.css` | `admin.css` + `woodex-tw.css` + **`woodex-v21.css`** |
| two palettes (`--ui-*` from woodex-ui, `--ds-*` from woodex-ds) shadowing each other | one token set from DESIGN.md §3 |
| light theme partly served by the old `:root` block in admin.css | `html:root` / `html.dark:root` — DESIGN.md values win |

`woodex-ui.css` and `woodex-ds.css` are deleted (`git rm`). Their component rules were folded into
`woodex-v21.css` with every `var(--ui-*)` / `var(--ds-*)` re-pointed at a v2.1.1 token, so the
feature screens that used them (chat bubbles, approvals, automation steps, builder) now render in
the new palette instead of the old one.

Two implementation notes worth keeping:

* **Specificity:** `admin.css` declares its legacy palette on `:root` (0,1,0). A plain `html {` rule
  (0,0,1) loses to it regardless of load order — that is why the light theme still looked like the
  old one until the token block moved to `html:root`.
* **Rule truncation:** an in-place edit that cuts a rule short leaves an unbalanced `{`, and the
  browser then discards every rule after it — silently. `tools/qa-p29/css-check.mjs` now detects it.
