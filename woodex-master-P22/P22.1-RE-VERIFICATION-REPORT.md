## 6. Defect found and fixed

### `/about/` — 209 px horizontal overflow on phones

**Symptom:** at a 390 px viewport the About page scrolled sideways by 209 px
(`scrollWidth` 599 vs 390).

**Root cause:** two competing rule sets for the same element.

* `about/index.html` (inline `<style>`) — at ≤600 px: `.ab-stats{grid-template-columns:1fr}`
  and `.ab-stat{display:grid;grid-template-columns:100px 1fr}` (a 100 px label
  column beside the text).
* `site-p21.css` — at ≤560 px: `#about-story .ab-stats{grid-template-columns:1fr 1fr 1fr}`.

`#about-story .ab-stats` (id + class) outranks `.ab-stats` (class) and the linked
stylesheet comes later in the cascade, so the stats row **stayed 3-across** while
each card kept its fixed 100 px inner column. Measured: three cards of
189 px + 201 px + 173 px = 563 px pushed into a 350 px container.

**Fix** (one line, `frontend-v1/assets/site-p21.css`):

```css
/* before */ @media(max-width:560px){#about-story .ab-stats{grid-template-columns:1fr 1fr 1fr;gap:8px}…}
/* after  */ @media(max-width:560px){#about-story .ab-stats{grid-template-columns:1fr;gap:8px}…}
```

The cards now stack full-width with the intended 100 px label + text layout, which
is what the inline ≤600 px rule always intended. Verified: overflow gone at
390 px, and the re-run sweep is clean at both widths.

**Because the source changed, the release zip was rebuilt** so the package stays
internally consistent (§2 re-verified against the new zip). Old → new:
`84cc33d4…` → `37f29edf…`.

**Two sweep flags, both investigated and confirmed correct by design:**

* `google_cfg` is reachable without sign-in. It returns **only** the OAuth
  *client ID* (`g_client_id()` → `jread(GOOGLE_FILE)['clientId']`), which is public

  separately guarded (`need($OA)`, or `fail('Only the owner can do this', 403)`).
  The sweep's `sec_` = owner-only assumption is simply wrong for these.

### 11.1 Google Map — grey grid showing over the map — FIXED

**Symptom:** the contact-page map had a grey "graph paper" grid printed across it.

**Root cause:** the shared theme rule

```css
main > section:not([class*="hero"]):not(.wx-stats) { padding-block: var(--wx-section) !important; }
```

matched `.ct-map` too, so the map section got **112 px of padding top and bottom**.
The iframe inside is `height:100%`, which resolves against the *content* box — so it
only filled 540 − 224 = **316 px**, leaving 112 px of the section's grid-pattern
placeholder background exposed above and below the map.

Measured before the fix: container 1440×540, iframe 1440×**315** at top offset
**113 px**, bottom gap **112 px**, `padding: 112px 0px`.

**Fix:** `.ct-map` is a full-bleed media block, not a padded content section, so it
now uses the theme's own opt-out class:

```html
<section class="ct-map wx-pad-0" id="contact-map" …>
```

(`v1-p21.css` already ships `body main>section.wx-pad-0:not(.wx-x){padding-block:0!important}`.)

Measured after the fix: container 1440×540, iframe 1440×**539**, top offset
**1 px**, bottom gap **0**, `padding: 0px`. The grid is now only the loading
placeholder, fully covered once the map paints.

*Note: the map tiles could not be visually confirmed inside this sandbox — it has no
route to `maps.google.com` (verified: HTTP 000). The layout fix itself is confirmed
by measurement; please confirm the tiles paint in your own browser.*

### 11.2 "Edit this page" button showing to everyone — FIXED

**Symptom:** a gold "Edit this page" pill sat in the bottom-left of every public page
in the preview.

**Cause:** `tools/frontend-v1-server.mjs` injected it into **every** public HTML
response, regardless of who was looking. It was never written into the site files (so
the live Hostinger site was never affected), but it cluttered the preview for ordinary
visitors.

**Fix:** the button is now injected `hidden` and only revealed when *that browser* is
signed into Woodex Admin — the admin keeps its token in `sessionStorage["wxaTok"]`, so
it appears for the owner and stays invisible for everyone else.

Verified in a real browser: **hidden** for a plain visitor, **visible** after signing
in as Master. The Lighthouse/PageSpeed exclusion is unchanged, so speed tests still
see the page exactly as on Hostinger.

### 11.3 FAQ "to theme style" — already correct, no change needed

The FAQ on `/contact/` uses the shared `wx-faq-sec` / `wx-faq-list` component
(`v1-p21.css`), the same component used by **10 pages** across the site (about,
book-a-visit, contact, projects/cafe-corner, projects/clinic-fit-out, …). Its markup is
identical to those pages and it renders with the theme's navy `rgb(12,22,40)`, Plus
Jakarta Sans headings and gold `+` affordances. There was no styling defect — what
looked wrong in the screenshot was the "Edit this page" pill from §11.2, now fixed.
