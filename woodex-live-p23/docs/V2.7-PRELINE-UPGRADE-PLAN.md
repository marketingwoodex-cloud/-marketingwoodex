### Design-token bridge

`admin.css` remains the runtime owner of the tokens (`--bg --card --line --txt --mut --pri …`).
The Preline sheet re-exposes them as Tailwind theme colours (`@theme inline`), so migration markup can be written
as `class="bg-card text-mut border-line rounded-wx shadow-wx text-pri"` and automatically follows the theme toggle:

| Utility | Resolves to |
| --- | --- |
| `bg-bg` `bg-card` `bg-card-elev` `bg-card-sub` | `var(--bg)` `var(--card)` `var(--card-elevated)` `var(--card-sub)` |
| `border-line` `border-line2` | `var(--line)` `var(--line2)` |
| `text-txt` `text-txt2` `text-mut` `text-mut2` | `var(--txt)` `var(--txt2)` `var(--mut)` `var(--mut2)` |
| `text-pri` `bg-pri` `bg-pri-fg` `text-ok` `text-warn` `text-bad` `text-info` | matching semantic tokens |

### The route sweep (`_tests/routes-sweep.test.js`)

Boots the real `admin/admin.js` in jsdom with a stubbed Admin API, then walks every sidebar route
and reports, per screen, the rendered byte count plus any thrown error. `status` / `me` / `pages`
are answered exactly as the backend would; every other action is answered with a *universal
payload* — a callable proxy that answers any property, iterates empty and coerces to 0 — so a
screen runs its real render path with an empty dataset. Two harness-carried states are reported
separately from failures: `SKIP` (the embedded `/builder/` iframe — its document is stubbed) and
`STUB` (a screen still on its Loading… shell because the payload fixture for its action lands in
Phase 3).

## 6. Credentials — what was found and what was done

The upgrade base carries the live administrative password and Telegram bot token in eleven places
(§5/D3), including the **public** `downloads.html` deployment guide and the SQL seed comment that
told the world the password for every seeded account. Everything found was scrubbed:

| File | Was | Now |
| --- | --- | --- |
| `.env` | other lineage's sheet with `APP_KEY`, DB password, bot token | rewritten as a reference sheet with placeholders and instructions; nothing in the codebase reads `.env` |
| `config.php` | literal `DB_PASS` fallback + literal `TELEGRAM_BOT_TOKEN` | `getenv(...) ?: ''` — the live values belong in `_private/db.json` and Admin → Integrations |
| `admin/admin.js` | password in the login fallback + 3 one-click SSO/demo pills | empty password, focused field; sign-in requires the real credential |
| `admin/index.html` | password in the login `value` + 2 page-builder placeholders | removed |
| `admin/admin-tg.js` | bot token as an input `value` **and** as a silent fallback when the field was empty | empty field + explicit "paste the token first" toast |
| `_database/woodex-database.sql`, `woodex-database.sql` | 6 seeded users sharing one bcrypt hash + the plaintext comment | hash replaced with a deliberately non-verifiable digest, comment replaced with install instructions — no seeded account can be signed into until an admin sets a password |
| `downloads.html` | public deployment guide printing the master credentials | points to `/wx-install.php` |
| `GO-LIVE-AUDIT-REPORT.md` | password in the M5 row | masked |
| `tools/**/*.mjs` (63 files) | password hardcoded in QA harnesses | `process.env.WX_PW` (+ `WX_DEV_PASSWORD` honoured where the script already used it) |
| `docs/V2.7-PRELINE-UPGRADE-PLAN.md` | this file mentioned the token identifier | masked |

**Both credentials must still be rotated**: they are in the git history of the base branch, and a
repository rewrite is the owner's call, not something this merge should do silently.

1. Add an `add(cat, id, name, icon, tags, html)` call in `tools/build-sections.mjs` (the file asserts exactly 70 blocks, so update that number in the same commit).

3. `node woodex-live-p23/_tests/sections.test.js` → must stay green.
4. `node tools/audit-classes.mjs` → a new class must be defined in `sections-v27.css` or a site sheet.
