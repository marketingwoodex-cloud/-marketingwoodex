## 2. Differences in Detail

### §1 Colour tokens — ✅ matches
| Token in plan | Found in code |
|---|---|
| Canvas `#050608`, card `#111318`, modal `#161b24` | Yes (`admin.css`) |
| Cyan `#00b8db`, neon `#00d3f2`, text on cyan `#04222b` | Yes |
| Light cyan `#007595`, light canvas `#f9fafb` | Yes |

### §2 Sidebar — ⚠️ partly matches
- **Hub names differ.** Plan: "Sales & CRM", "Admin & System". Admin: "SALES", "ADMIN & SETTINGS". Groups are otherwise the same (OVERVIEW, SALES, CONVERSATIONS, WEBSITE & CMS, ADMIN & SETTINGS, ME).
- **Accordions match:** Quotes & invoices, WhatsApp.
- **Routes differ:** the plan lists "System check (#/health)", but the admin has its own `#/system` screen. The plan's "Connect WhatsApp (#/settings)" is `#/settings/connections`.
- **Rail toggle — fixed in this round.** Before the fix, the top-bar button set a `mini` class that the CSS only half-supported, so labels overlapped the icons. The sidebar's own `#rail` button had no click handler at all. Both buttons now use one toggle with a `rail` class (72 px), and the choice is remembered. On phones the same buttons open the slide-in drawer. Nav links have tooltips in rail mode.
- **Integrations** is under ADMIN & SETTINGS (`#/settings`). It was hard to find because the collapsed sidebar hid the labels. It is also reachable with Ctrl+K by typing "integ".

### §3 Preline blocks across 52 screens — ⚠️
The plan says 52 screens. The nav has 62 links and 56 screens render. The count is different, but the block patterns are present (KPI cards, tables, kanban, form builders, chat, CMS grids, health checklists).

### §4 Floating chat dock — ⚠️
- The dock element is `#cx-bub` (in `admin-chat2.js`), not `#cx-dock` as the plan says.
- The bubble colour tokens from the plan (`#0b2230`, `#1e293b`, `#04222b`) are present.
- **Auto-open on an inbound message was not tested.** It needs a real chat message.

### §5 Database architecture — ❌
- **Plan:** MySQL 8 with pooling and indexes in production, plus a flat-file `_private/admin-db.json` for local work.
- **Built:** MySQL only, configured by `_private/db.json` (written by the setup screen). No flat-file mode exists.
- **Effect:** a local preview needs a running MySQL server. This is how the site runs now.
- **Decision needed:** build the flat-file fallback, or drop it from the plan.

### §6 Production packages — ⚠️
The zip files are on branch `8a776c65`. Their contents were not checked in this review.

## 3. Fixed in This Round (v2.5.5)

| Issue | Cause | Fix |
|---|---|---|
| Sidebar collapse did not work | Top-bar button used a `mini` class that the CSS only half-supported; sidebar button `#rail` had no handler | One toggle for both buttons; `rail` class (72 px); preference saved in `localStorage`; sidebar's own toggle hidden while collapsed |
| "Add new lead" modal cut off by the sidebar and shown twice | The modal used class `.modal-overlay`, which had no CSS, so it sat in page flow under the sidebar; each click added a copy | `.modal-overlay` is now fixed and centered; only one copy is kept; modal header styled so the × sits beside the title |
| Bank deposit reconciliation missing | Not built | New panel on the Payments screen: paste or upload a bank statement CSV; credits are matched to payments by amount and date (±3 days), with receipt, invoice, reference and client name boosting the match. Matches are labelled "Matched" or "Amount & date only". Runs in the browser; nothing is saved. |
| WhatsApp hourly heatmap missing | Not built | Insights screen: 7 × 24 heatmap of visitor messages in Karachi time, computed by the server from the same chat data |

Verified in headless Chromium with sample data fed through request interception (the sandbox has no real invoices or chats):
- Sidebar: 280 px → 72 px, labels hidden, content moves to match.
- Add-lead modal: one overlay, centered over the page, sidebar not covering it.
- Reconciliation: 2 credits matched, 1 unmatched credit, 1 payment not on the statement.
- Heatmap: 168 cells rendered.
